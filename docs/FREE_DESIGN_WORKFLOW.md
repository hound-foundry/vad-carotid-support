## Working local path

The default workflow has no design-service subscription or runtime library additions. Normal computer, coding-agent and hosting costs are separate; “free” does not promise free AI compute or app-store distribution.

```text
npm run design:check
npm run build:web
npm run design:kit
npm run design:preview
```

Open `http://localhost:4180/_design/`. It shows the real exported app in an iframe, selectable across ten routes and four review sizes. Token-theme selection shows the four resolved source palettes; the app uses its own Text and display settings. All controls are labelled and keyboard reachable. This is a development workbench, not another patient route or navigation system.

Exports under ignored `output/design-kit/`: design guide, app profile, source/resolved theme tokens, numeric authored metrics, editable SVG palette and a manifest identifying source files, the web entry bundle and six saved-data keys. The SVG is a palette, not a recreated screen. This tool reads source/build files only. It never opens browser storage, exports notes/cards, contacts a service, installs packages or changes the app. Fresh blank Home captures are optional separate import assets, not automatically regenerated by `design:kit`.

The workbench origin has its own browser storage. Use synthetic fixtures there. Page/size selection reloads the embedded page; use the app's own navigation to test interrupted return. Saved fixtures stay on that origin until explicitly deleted. The workbench is served on loopback, independently from the user's usual `localhost:4173` preview.

## Useful additions from the second research note

Prioritize tools that answer a concrete question about the working app. Keep one editable design destination and the source-derived workbench; adding every generator would duplicate work.

| Addition | What it would help us check | Current evidence and limits |
|---|---|---|
| [NVDA](https://www.nvaccess.org/download/) | Free, open-source Windows screen reader: spoken headings, field labels, navigation, preview announcements and return after interruption | Official download/source checked. Not run; a real screen-reader journey remains required |
| [Accessibility Insights for Web](https://accessibilityinsights.io/docs/web/overview/) | Open-source Chrome/Edge extension: automated findings, tab-stop visualization and guided manual checks | Official documentation checked. Not installed/run. Its documented assessment covers WCAG 2.1 AA; add our WCAG 2.2 checks separately. Telemetry is optional; use disposable synthetic fixtures |
| [axe-core](https://github.com/dequelabs/axe-core) | MPL-2.0 engine for later repeatable automated web accessibility regressions | Source/licence checked; not installed/run. An engine result cannot establish usable reading, fatigue tolerance or full accessibility |
| [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview) | Open-source Chrome DevTools audits for page performance, accessibility and layout stability | Official docs checked; not run. Prefer the local DevTools path for this preview; a score is not a patient usability verdict |
| [React Native DevTools](https://reactnative.dev/docs/react-native-devtools) | Inspect the eventual native app's components and runtime using the existing React Native stack | Official docs checked; no native run. Android SDK/emulator and physical-device checks remain missing |
| [Storybook](https://storybook.js.org/docs) | Open-source isolated component states and documented examples if the component library grows | Official docs checked; not installed. Defer while the existing route workbench is enough; hosted visual-testing products have separate costs |

The locally installed UI/UX Pro Max search returned both minimum AA and enhanced AAA focus-visibility guidance, correctly distinguishing them. This verifies the search tool and relevance of that result, not the app's compliance. Moda's readiness check and SVG Lab's access check verify connections only. See [readiness.json](design-tools/readiness.json); no credentials or account identity are recorded.

Reuse Interface Design for hierarchy and the measured guide for tokens. Keep Moda/SVG Lab as optional editable-artifact tools, and Stitch as the already working reference destination. Sleek's one-time trial and Figma's quotas should not become dependencies of a free repeatable workflow. Blushie's glass/embossed material ideas are not this project's selected direction; the calm opaque reading surfaces and current teal colours remain intact.

For a later design change, select one task, draft it in the chosen canvas, inspect 320px/390px and long-content states, then implement it through existing shared components. Run the affected real journeys and storage/export regressions. Provider screenshots, AI reviews and diagnostics remain separate from patient feedback, clinical review and assistive-technology testing.

## Preserve structure, with evidence

Route presentation stays in `app/`; shared accessible wrappers/theme stay in `src/components/`; separate feature models/storage/exports stay in `src/features/`; authored content and sources remain separate. No framework migration, native library swap, new account flow, backend, automatic save/export or clinical wording change is part of this workflow.

`design:check` rejects a different framework/profile, missing routes/source files, changed saved-key count, missing explicit Save/Export declarations and palette drift. These profile declarations do not prove runtime privacy; existing feature/privacy tests and affected browser journeys check actual behavior. Source fingerprints identify protected implementation files; they do not prohibit later reviewed edits. A generated screenshot/HTML is a visual target, never proof of real storage or handlers. Bring accepted changes into the current components and rerun tests/typecheck/export plus actual affected browser journeys.

Atlas remains separate. The current connector status still reports `C:\Work\GameDev\STRIFE`, so it was not used as evidence for this Expo project. No index was retargeted and no Godot dependency was added. See [ATLAS.md](ATLAS.md).

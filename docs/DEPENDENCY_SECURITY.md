# Dependency security review

Checked on 13 October 2026 against the current npm lockfile, npm audit data, npm registry releases, GitHub Dependabot alerts and Expo’s SDK 57 documentation. This is a maintenance note, not a complete security audit.

The lockfile now resolves Expo 57.0.28 and Expo Router 57.0.26 within the ranges already declared in `package.json`. The `xcode` build-tool dependency is scoped to `uuid` 11.1.1, which includes the bounds-check fix. A smoke check confirmed the installed `xcode` package and `uuid.v4()` load successfully.

GitHub reported four open Dependabot alerts on the default branch at the last check. The `uuid` alert is fixed on this project branch by the `xcode` override; it will remain visible against the default branch until that change is merged. The current branch addresses the decoder advisory with a private CommonJS compatibility build in `vendor/decode-uri-component`: it adapts the upstream 0.5.0 implementation’s ESM export for the synchronous CommonJS call made by Expo Router’s query parser. A stress test covers a long malformed query value; `npm audit` no longer reports this advisory. Recheck the compatibility build when the router or query parser changes.

- [`braces` GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm): Expo Metro’s file-matching build chain resolves `braces` 3.0.3. The advisory lists no patched version.
- [`node-forge` GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv): Expo CLI code-signing tooling resolves `node-forge` 1.4.0. This advisory also lists no patched version. The earlier `node-forge` certificate-chain issue is fixed in 1.4.0; this is a separate later finding.
- [`decode-uri-component` GHSA-vcc3-ghjq-m6fr](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr): `expo-router` 57.0.26 includes `query-string` 7.1.3, which synchronously calls the CommonJS decoder while parsing route query parameters. The local package adapts the [upstream fixed implementation](https://github.com/SamVerschueren/decode-uri-component/blob/fa479dafeede7bedf04e5c89aa78f2a78c664005/index.js); this is a compatibility build, not an independent security review.

`npm audit` reports 18 affected package nodes across multiple paths, all high severity; these group into the two distinct unresolved upstream findings above. On the check date, npm’s latest stable tags were Expo 57.0.28 and Expo Router 57.0.26; [Expo’s current stable SDK reference](https://docs.expo.dev/versions/latest/) lists SDK 57. Do not move this project to the SDK 58 router `next` line or a canary solely to silence an alert; [Expo recommends incremental upgrades](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/) and checking release notes.

The two remaining advisories affect `braces` and `node-forge` in the local Expo/Metro build and signing toolchain. Avoid serving untrusted project changes through local development servers and keep private notes out of URL parameters. These are mitigations only; they do not clear the advisories.

Weekly Dependabot updates are configured for npm packages and GitHub Actions in `.github/dependabot.yml`. Review and test each update; automated update PRs do not constitute approval. Do not use `npm audit fix --force` to downgrade the Expo SDK. Recheck advisories after upstream releases and before distribution. Keep this gate visible in the release checklist; green project CI does not mean the dependency tree is vulnerability-free.

The card-export dependency update exposed an npm-version difference: npm 11.17 on Windows removed the existing nested Expo optional peer `react-native-worklets` 0.10.4, while the CI runner's npm 10.9.9 required its lock record. The known record and integrity were restored. Locked-install dry runs now pass with both npm versions. Preserve and recheck that optional peer when regenerating this lockfile; the project does not use it to introduce interface animation.
